## Task H1 — `StartOneshotPatrol` stamps wp0 dwell

**Root cause:** `internal/mobs/patrol.go:50-64` sets `patrol_dwell_remaining = 0` on every patrol start. When the mob arrives at wp0 (walks to it from wherever they started), `patrolTickPlan` (`internal/hooks/NewRound_IdleMobs_patrol.go:56-75`) sees `RoomId == currentWaypoint.Room` AND `dwellRemaining == 0`, fires `WantsAdvance`, skipping the `WantsDwellWait` branch. The arrival-event guard at `:130` only fires when `wp0.DwellRounds == 0`, but every authored patrol has wp0.DwellRounds > 0, so the `caravan_vendor` / `forager_vendor` arrival event is never emitted for wp0. The first vendor stop is skipped entirely.

This single bug manifests as BOTH:
- **Lars's first vendor skip** (smoketester BUG-01)
- **Tova's "despawn"** (observer at Tova's first vendor sees her arrive and instantly walk off without selling)

**Files:**
- Modify: `internal/mobs/patrol.go:61`
- Test: `internal/mobs/patrol_test.go` (add new test)

## Task H5 — `ClearOneshotPatrol` on forager state-transition cleanup

**Root cause:** `tickForagerRecalling` (`internal/behaviortree/actions_forager.go:428`) and the HP-emergency recall short-circuit (`:59-66`) both transition the forager out of an active delivery patrol, but neither calls `mobs.ClearOneshotPatrol(mob)`. If a delivery patrol is interrupted by HP-emergency or hits home-fallback, the mob ends up at sanctuary with `mob.PatrolId` still pointing at the delivery patrol. Next idle tick, the patrol executor reads the stale ID, sees the mob at the (coincidentally-matching) terminal waypoint with `dwell_remaining=0`, emits a phantom `PatrolCompleted` event, and the completion listener fires a spurious state transition.

## Task H8 — Add `forager_check_thresholds` btree primitive

**Root cause:** The forager YAML archetype at `_datafiles/world/dogmud/behaviors/archetypes/forager.yaml` has structure:

```yaml
- type: sequence
  event: mob_idle
  children:
    - condition: forager_state_is_foraging
    - selector:
        - try_salvage
        - try_forage
        - wander_territory
```

When `try_forage` or `wander_territory` succeeds (which they almost always do in workable territory), the top-level archetype selector short-circuits Success and **never reaches the `forager_step` action where the carry-cap and fatigue threshold checks live** (`actions_forager.go:101-105`). Foragers accumulate cargo past their carry capacity (~200% observed on prod) without ever transitioning to TravelingToDropoff.

**Fix:** add a new btree action `forager_check_thresholds` and register it as the FIRST child of the inner selector. It reads carry-ratio and fatigue, transitions state + returns Success if a threshold is hit (selector short-circuits — fine, state changed), or returns Failure otherwise (selector falls through to try_salvage/try_forage/wander as normal). Move the fatigue increment + threshold check from `actForagerStep` into this primitive so it runs every Foraging tick.

**Files:**
- Modify: `internal/behaviortree/actions_forager.go` (move check logic into new function, remove from `actForagerStep`)
- Modify: `internal/behaviortree/actions_forager.go` (register the new action in the action registry)
- Modify: `_datafiles/world/dogmud/behaviors/archetypes/forager.yaml` (add the new primitive)
- Test: `internal/behaviortree/actions_forager_test.go` (new tests for the primitive)

```go
// actForagerCheckThresholds is the chunk 3.8 hotfix replacement for
// the fatigue/carry-cap check that used to live at the top of
// actForagerStep but never fired because the YAML archetype's inner
// selector short-circuited before reaching forager_step.
//
// Registered as a btree action so it can run as the FIRST child of
// the foraging selector. Returns:
//   - Success if a threshold was hit and state was transitioned
//     (selector short-circuits, which is correct — the mob is no
//     longer in Foraging next tick)
//   - Failure if thresholds are not yet hit (selector falls through
//     to try_salvage / try_forage / wander_territory as normal)
func actForagerCheckThresholds(
	profile *forager.ForagerProfile,
	mob *mobs.Mob,
	ctx *EvalContext,
) Result {
	cfg := configs.GetBalanceConfig()

	fatigue := getIntFromState(ctx.MobState, keyFatigueTimer) + 1
	ctx.MobState.Set(keyFatigueTimer, strconv.Itoa(fatigue))

	if fatigue >= fatigueLimit ||
		carryRatio(mob) >= float64(cfg.ForagerCarryThresholdPct) {
		transitionForager(ctx.MobState, forager.StateTravelingToDropoff)
		return Success
	}
	return Failure
}
```

The remaining `switch cur` for non-Foraging states stays.

Register the new action in the btree action registry (`internal/behaviortree/`). Match the pattern used by `try_forage` exactly — same registration style, same dispatch signature.

```go
// pickupQualifies reports whether the vendor stock entry should be
// considered for caravan pickup. Two qualifying paths:
//
//  1. Zone-source bucket match — the item is in pickupBuckets per
//     economy.BucketFor. Pre-3.8-hotfix this was the only path.
//
//  2. Component-and-not-finished-good — the item is flagged
//     IsComponent (raw material), AND its Type is not a finished
//     good (weapon, armor, etc.). Lets crafting materials flow
//     freely cross-city without sweeping up crafted output.
func pickupQualifies(itemId int, pickupBuckets []string) bool {
    bucket := economy.BucketFor(itemId)
    if bucket != "" && slices.Contains(pickupBuckets, bucket) {
        return true
    }
    spec := items.GetItemSpec(itemId)
    if spec == nil || !spec.IsComponent {
        return false
    }
    return !isFinishedGood(spec.Type)
}

// isFinishedGood reports whether an item type represents a player-
// usable end-product (worn, wielded, consumed) rather than a raw
// crafting material. Caravan cross-city distribution moves materials
// only — finished goods stay where they're crafted.
func isFinishedGood(itemType items.ItemType) bool {
    switch itemType {

        items.ItemTypeBody,
        items.ItemTypeLegs,
        items.ItemTypeOffhand,
        items.ItemTypeHead,
        items.ItemTypeGloves,
        items.ItemTypeFeet,
        items.ItemTypeBack,
        items.ItemTypeNeck,
        items.ItemTypeRing,
        items.ItemTypeWrist,
        items.ItemTypeShoulders,
        items.ItemTypeBelt,
        items.ItemTypeTail,
        items.ItemTypePotion,
        items.ItemTypeFood,
        items.ItemTypeComponentBag:
        return true
    }

}
```

```go
// comes in display-case, e.g. "Stillwater" or "Thornwall City").

// is case-insensitive and word-boundary-aware (display "Thornwall City"
// → "thornwall_city").
//
// Additionally consults a territory→zone alias map so non-prefix-match
// pairings work (e.g., Halix's "ironwind_steppe" delivers to
// "Thornwall City" / "thornwall_city").
func territoryMatchesZone(territory, zone string) bool {
    t := util.ConvertForFilename(territory)
    z := util.ConvertForFilename(zone)
    if t == z {
        return true
    }
    if alias, ok := territoryZoneAlias[t]; ok && alias == z {
        return true
    }
    // Prefix match (territory begins with zone + "_"), case-normalized.
    if len(t) > len(z) && t[:len(z)] == z && t[len(z)] == '_' {
        return true
    }
    return false
}

}
```
