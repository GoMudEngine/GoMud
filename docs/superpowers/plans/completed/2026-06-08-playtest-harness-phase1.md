# Playtest Harness Adoption — Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace DOGMud's file-IPC AI-testing stack with the GoMud playtest harness's `mudagent` adapter + the vendored `playtest` server module (beacons, safe mode, death protection, sandbox) + a DOGMud `/playtest` driver reading a self-contained `tools/playtest/` overlay; retire the old stack.

**Architecture:** Approach A — the harness repo (`~/workspace/gomud-playtest-harness`, env `GOMUD_HARNESS_DIR`, default `../gomud-playtest-harness`) stays engine-agnostic; DOGMud owns a thin content overlay + driver and vendors only the server module. The module's engine prerequisites (AI port `ConnAI`, `IsAI`, gmcp `SendGMCPEvent` export, events/rooms) are **already present in DOGMud** (verified) — the only code adaptations are the beacon payload (DOGMud's pools are Health/Stamina/Conviction, not Mana) and death-protection (DOGMud has no `Character.ExtraLives`).

**Tech Stack:** Go (server module, in DOGMud's main module — modules use `github.com/GoMudEngine/GoMud/...` import paths and have **no per-module go.mod**; `modules/all-modules.go` is `go generate`-d). YAML/Markdown (overlay). The prebuilt `mudagent` binary + the harness driver are reference sources at `$GOMUD_HARNESS_DIR`.

**Spec:** `docs/superpowers/specs/2026-06-08-playtest-harness-adoption-design.md`
**Reference (harness) docs:** `module/playtest/*.go` (source to vendor), `docs/plans/2026-06-05-playtest-module.md`, `docs/plans/2026-06-05-phase2-beacons.md`, `docs/plans/2026-06-05-framework-content.md`, `.claude/commands/playtest.md` (driver to adapt), `framework/{engine-profile.yaml,targets.yaml,personalities,goals/SCHEMA.md}` — all under `$GOMUD_HARNESS_DIR`.
