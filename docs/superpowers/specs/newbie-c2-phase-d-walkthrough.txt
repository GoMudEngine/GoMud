2. TWO LATENT BUGS FOUND & HANDLED (would have silently broken rewards)
--------------------------------------------------------------------------------
A. REWARD-KEY LOADER GOTCHA (quests.QuestReward).
   The quest loader uses gopkg.in/yaml.v2, which binds a TAG-LESS struct field
   to its lowercased name with NO underscore handling. The reward hook
   (Quest_HandleQuestUpdate.go) reads quests.GetQuest(...).Rewards — the legacy
   tag-less QuestReward. So reward-block fields load ONLY from no-underscore
   keys: itemid, skillinfo, buffid, playermessage, roommessage, roomid, spellid.
   snake_case (item_id, skill_info, player_message) silently DOES NOT load.
   - Older quests (3-20) correctly use no-underscore -> work.
   - A few newer quests (1 skill_info:map:1; 30/31 player_message) mistakenly
     use snake_case -> those reward fields silently no-op. (Pre-existing; NOT
     fixed here — flagged as a separate latent cleanup. Quest 1 is the retiring
     Sanctum trials; 30/31's are flavor player_messages.)
   - FIX APPLIED: my quests 32/33/34 use the working no-underscore keys
     (skillinfo/itemid/playermessage/roommessage). I briefly added snake_case
     yaml tags to the struct but REVERTED — that would have broken all ~18
     older no-underscore quests. The struct is back to tag-less (plus the
     pre-existing stat_info/rep_* tags) with a loud explanatory comment.
   - Trigger ACTIONS / CONDITIONS are unaffected: the questengine TriggerDef/
     Conditions/ActionDef ARE properly snake_case-tagged (verified has_flag,
     send_text, give_item, set_flag, train_stat all load), so my triggers'
     snake_case keys are correct.

B. STRAY .clone/ DIRECTORY.
   A content subagent mistyped the worktree path (.clone instead of .claude) and
   wrote quest 32 + dialogue 9108 there. Recovered both into the real worktree;
   deleted the entire stray c:/Users/Calabe Davis/workspace/DOGMud/.clone tree
   (also held a duplicate 9114 mob — the real one was already correct).
