## BUG-04 (High) — guards walk into the cell and fight the jailed player
**Root cause:** `RunGuardEnforcement` (internal/justice/enforce.go) has no
exemption for already-jailed players. A patrolling city_guard (maxwander:2)
wanders `down` into cell 5105 and its Arrest/Attack branch fires on a player
already serving a sentence.
**Fix (user-approved design: "jailed = exempt"):** In `RunGuardEnforcement`'s
per-player loop, right after the existing `HasBuffFlag(NoAggroTarget)/IsHidden/
Health<1` continue-check (enforce.go ~line 134-137), add:
```go
		// A player already serving a sentence is in custody — guards leave
		// them be (no re-arrest, no attacking someone locked in a cell). 5.1c.
		if _, jailed := miscDataRound(user.Character.MiscData, keyJailUntilRound); jailed {
			continue
		}
```
`keyJailUntilRound` is defined in arrest.go (same package) — directly usable.
(Consider also: give cell 5105 something that keeps wandering guards out, or set
city_guard maxwander so it can't path into the cell — but the exemption is the
robust single-point fix.)

## BUG-03 (High) — payfine/serve doesn't fully clear wanted status → immediate re-arrest
**Root cause:** `ExecuteArrest` (arrest.go ~line 254) stamps crime ids only for
`guardFactions[0]` = `thornwall_guards`. But guards ALSO belong to
`thornwall_citizens`, and `Verdict` checks the whole faction+ally set. A crime
against `thornwall_citizens` stays unresolved after release → Verdict returns
Arrest again → re-arrested on the spot.
**Fix:** Make `ResolveDetention` (arrest.go ~line 300) clear across the
arresting faction **+ its allies** (the same set Verdict uses), comprehensively
(live query, not just the stamped ids):
1. Add a crimes seam near the others (arrest.go ~line 58):
   `aCrimesForFactionFn = crimes.AllForFaction`
2. Rewrite ResolveDetention's clearing section:
```go
	faction, _ := miscDataString(player.MiscData, keyJailFaction)

	// Faction set the sentence answers for: arresting faction + its allies
	// (matches Verdict's set), so release clears the player's record with the
	// whole town — guards belong to thornwall_guards AND thornwall_citizens,
	// and an unresolved crime against either would re-trigger arrest.
	factionSet := map[string]bool{faction: true}
	for _, a := range alliesFn(faction) {
		factionSet[a] = true
	}
	for f := range factionSet {
		for _, c := range aCrimesForFactionFn(f, false) {
			if c.PerpType == crimes.PerpPlayer && c.PerpId == userId {
				aResolveCrimeFn(f, c.Id, "served sentence")
			}
		}
	}
	for _, b := range aOpenBountiesFn(userId) {
		if b.Issuer.Type == bounties.IssuerFaction && factionSet[b.Issuer.Id] {
			aWithdrawFn(b.Id)
		}
	}
	floor := aRepResetFn()
	for f := range factionSet {
		if aGetRepFn(f, userId) < floor {
			aSetRepFn(f, userId, floor)
		}
	}
```
   (Removes the old stamped-id `parseCrimeIds(crimeIdsRaw)` loop and the
   single-faction bounty/rep blocks. `crimeIdsRaw` local must be deleted to
   avoid unused-var; `parseCrimeIds` may become unused — unused funcs are OK in
   Go, or delete it too. `alliesFn` is the justice-package seam in justice.go.)
3. Update the ResolveDetention seam test to assert clearing across the ally set.

## BUG-02 (High) — flee bypasses jail lockdown
**Root cause:** `no-go`/NoMovement blocks `go <dir>` (go.go:89) but `flee`
(internal/usercommands/flee.go) never checks it — flee transitions to
Disengaging and the round driver moves the player out of the cell.
**Fix:** At the top of `Flee()` (flee.go, after the func opens, before the
disengage logic at line ~14), add:
```go
	if user.Character.HasBuffFlag(buffs.NoMovement) {
		user.SendText(messaging.CategorySystem, `You're locked in — there's nowhere to flee to.`)
		return true, nil
	}
```
Add `"github.com/GoMudEngine/GoMud/internal/buffs"` to flee.go imports.
(NOTE: once BUG-04 lands, jailed players won't be in combat, so this rarely
triggers — but it's a real lockdown hole worth closing. Verify flee.go's import
block + that buffs.NoMovement is the right flag name.)

## BUG-01 (Medium) — payfine prints the release line twice
**Root cause:** Jailed buff 88's `end_user_text` is
"The cell door swings open. You are free to go." `ResolveDetention` (arrest.go
~line 345-349) ALSO manually SendTexts that exact line. `player.RemoveBuff(88)`
fires end_user_text → two identical messages.
**Fix:** DELETE the manual release SendText block in ResolveDetention (lines
~345-349, the `if u := users.GetByUserId(userId); u != nil { ... "The cell door
swings open..." }`). The buff's end_user_text already covers release flavor on
BOTH the payfine path (RemoveBuff fires it) and the timer-expiry path (natural
expiry fires it). Keep payfine's own "You count out N gold..." line (jail.go:81)
— it's distinct and useful. Verify in a re-smoke that exactly ONE door message
shows on both payfine and serve-out.
