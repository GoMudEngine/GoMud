The World Builder — Admin Guide

Basics Rooms Items Mobs Dialogue Zones Quests Behaviors Where the tabs meet

/build is the full content workshop: six tabs (plus the dialogue panel inside Mobs) that together cover everything a zone is made of. This guide explains each tab in depth, with things worth trying, and — because no piece of content lives alone — how the tabs feed each other.

Basics that apply everywhere

  • Saves are live immediately. Every editor hot-swaps its cache on save: the very next round, room load, talk, or combat swing uses your edit. No reboot, ever. Test in-game the moment you save.
  • Refusals vs warnings. Red text above a form is a refusal — the save did NOT happen, and the message names the exact field/node/trigger at fault. Amber text is a warning — the save DID happen, and the note stays on screen until fixed. Nothing is ever silently dropped.
  • First-save churn. Hand-authored YAML isn't in the editors' canonical form. The FIRST save of an old file rewrites it (key order, wrapping); every save after is a minimal diff. One-time, expected.
  • Comments do not survive saves. A marshal cannot keep # comments. Editors with comment-rich content (Behaviors especially) show a banner when a file still has them — move anything worth keeping into the note/notes fields those editors provide.
  • After a server restart, reload the page. A tab that outlives a restart has a dead connection; any action will toast "Not connected — reload the page." After a deploy that touched the builder itself, hard-refresh (Ctrl-F5) — browsers cache the scripts.
  • Deletes are guarded. Anything still referenced elsewhere refuses to die and lists every holdout verbatim: a mob spawned by rooms, a quest granted by dialogue, an archetype worn by mobs. Fix the references first; the list is your worksheet.

Rooms

The map canvas IS the editor: click a room to inspect it, click a ghost cell (dimmed outline next to an existing room) to create one there. The toolbar's zone/plane/floor selectors move you around the world; the admin map is unfogged — you see every room, visited or not.

What's on the room form

  • Title + description — what players read. Descriptions hard-wrap around 78 columns for MUD clients; write prose, not instructions (the quest log and hints carry instructions).
  • Biome, symbol, legend, music — map rendering and ambience.
  • Flags — bank, storage, pvp, character room.
  • Nouns — the look-targets. Keys are space-separated (notice board, never notice-board); players reach them with look notice board.
  • Idle messages — ambient lines the room emits.
  • Exits — compass directions (n/s/e/w/up/down) plus named portals. Compass exits must stay Cartesian-consistent: reciprocal, and matching the grid. The editor refuses placements that would collide.
  • Spawns — what lives here. Each entry is exclusively a mob, an item, or gold; respawn timing is written in real time (15 real minutes); items/gold can route into one of the room's containers, picked from a dropdown of containers the room actually has. Reorder and per-spawn overrides live in the Advanced drawer.
Try: pick a quiet room and give it life without touching a file: add a noun (old plaque → a paragraph of lore), an idle message, and a spawn entry for a critter with 30 real minutes respawn. Walk there in-game — all three are live.
The room's spawn list is the ONLY place spawn locations exist. Mob templates do not know where they spawn — see Where the tabs meet.

Items

The item list is searchable by id or name; the form covers the full item schema: type/subtype (weapon classes, armor slots, caster weapons), damage/mitigation numbers, weight, value, component and crafting fields (component_tag, salvage returns), and the Advanced drawer for the rare fields.

Things worth knowing

  • Multi-word names are authored with spaces (lake iron nodule) — the parser matches whole phrases; hyphens make items unfindable.
  • Mitigation is per-channel: physical_mitigation / magical_mitigation / conviction_mitigation, integer percentages.
  • Items with is_component: true auto-route into component bags on pickup; component_tag is what recipes and salvage returns match on.
  • Deleting an item is guarded by everything that references it: shop stock, loot pools, spawn lists, equipment, quest rewards, dialogue givesItem.
Try: clone a niche reward. Create an item, give it a flavorful two-line description, modest stats, and set its value; then open the Quests tab and hand it out as a quest reward — the reward field's item picker will already know it.

Mobs

Everything a creature or NPC is: identity, stats, commerce, AI hooks. The zone filter narrows the list; badges mark non-combatants, schedules, and shops.

The form, top to bottom

  • Test spawn — an admin tool ONLY: drops a disposable copy in a room you pick, so you can fight/talk to your edits immediately. It says nothing about where the mob really spawns (that's rooms).
  • Dialogue… — opens the dialogue panel for this mob. Reads "Add dialogue…" for a mute mob.
  • Identity — name (renames move the file AND the mob's behavior tree), description, species, adjectives, groups.
  • Stats & combat — stat pool + per-stat training, archetype (fighting/casting stat split), auto-aggro, AI profile, activity/wander.
  • Inventory & commerce — equipment by slot, carried items, loot pool, drop chance, shop stock, crafter fields. Every id input is a picker with names.
  • Aliveness — schedule (daily routine), patrol route, relationships, known facts.
  • Advanced — behavior archetype (with jumps into the Behaviors tab), buffs (e.g. spawn hidden), quest flags, mutations, overrides, non-combatant and immunity flags.
Try: make a shopkeeper from nothing: + New Mob in a zone → name and describe them → non_combatant on → add shop stock rows → give them a schedule if the zone has one → Save → test-spawn them next to you and list. Then open Dialogue… and give them a greeting and a "wares" pattern so they feel staffed, not stocked.

Dialogue (inside the Mobs tab)

Everything an NPC can say. Opened per-mob from the mob form. Three layers, from ambience to conversation:

LayerFires onUse for
Greetingsa player entering the room (once per player per NPC per boot; skipped for sneakers and busy NPCs) flavor one-liners, mood-matched
Patternsask <npc> <topic> keyword matchthe NPC's standing FAQ — town, trade, rumors. An empty-string keyword is the catch-all.
Treetalk (root) and ask (nodes, matched IN ORDER)real conversation and ALL quest logic: gated root variants, quest-granting nodes, requires/unlocks chains.

House rules the editor enforces

  • Refused: a grantsQuest without BOTH its own token and the quest's -end token in questExcluded (else completed players get re-offered); grant nodes missing quest/task triggers; grant nodes listed after lore nodes (order is matching priority); semicolons in spoken text; unknown tokens/flags/items.
  • Warned: undiscoverable trigger words (if no hint or text ever shows the word, the branch does not exist); memory expiry set (bricks quest chains — timed quests only).
  • NPC text is first person. Hints are the narrator: "You could ask about the marriage," never "Ask her why she left."
Try: the smallest quest-giver: a root that mentions a problem, a hint pointing at it, ONE node with triggers problem, help, quest, task that grants the quest — with both exclusions — and a root variant for while it's active. Then talk/ask it live; edits apply mid-conversation.

Zones

The container level: create zones, edit zone config, rename, delete.

  • Create — allocates the folder tree and a starter room on a fresh plane. non_cartesian zones (mazes, toroidal spaces) must live on their own plane, never plane 0 — one non-Euclidean room on the overworld plane silently disables map enforcement for EVERYTHING, so the editor refuses the combination outright.
  • Config — biome, region, instanced-zone settings (entry room, cost, duration).
  • Rename — the heavyweight: moves ten directories, rewrites zone: across every content tree, rekeys caches. Refuses while players are inside. Players re-explore renamed zones (fog resets by design).
  • Delete — refuses unless the zone is empty: rooms beyond the root, any authored content, or inbound exits from other zones all block it, each listed.
Try: a sandbox zone for experiments: + New Zone ("Test Yard"), build three rooms in it, spawn things, break things — then delete the rooms and the zone when done. Nothing you do there can leak into the live world unless you link an exit to it.

Quests

The full quest machine: identity, steps, rewards, flag declarations, and the trigger DSL. This is the deepest tab; think of it as three layers.

Steps — the player-visible skeleton

Ordered stages, each with a quest-log description and hint. The map target controls the minimap marker during that step: a room id points there; 0 infers the destination from a room_enter trigger gated on the step; the "no marker" box (writes -1) deliberately draws nothing — for action steps (craft this, kill those) with no travel destination.

Rewards — paid on completion

Gold, an item, a buff, a spell, skill/stat raises, recipes, an item stockpile, messages, a teleport, faction rep, and a chain token that grants the next quest. All picker-backed.

Triggers — the machinery

Each trigger = an event (what the world watches for), optional filters (which mob/item/room/command), conditions (which players it fires for), and an ORDERED action list. The event select explains each event inline; the two easily-confused ones: command fires when an instrumented command SUCCEEDS, command_issued fires on the keystroke, success or not.

Actions cover the vocabulary: grant tokens, consume/give items, gold in both directions, scripted NPC lines with per-line delays, spawns, exit locks, teach/train/learn, buffs, teleports, flags, faction rep, bounties — and sequence, a timed scene with its own on-complete actions and an optional movement lock.

What the editor enforces

  • Refused: tokens that resolve to no quest step; undeclared flag keys/values (this used to PANIC the next boot — now it's a polite red message); ids that don't exist — mobs, items, rooms, buffs, spells, skills, recipes, factions — each named with its exact location ("trigger 3 action 2 spawn_mob: mob 999 does not exist").
  • Warned: a step that no trigger, reward chain, or dialogue file grants (players cannot reach it); an npc_say speaker with no dialogue file; a map target no trigger references.
Try: a delivery quest end to end: + New Quest → describe it → step start (map target: the recipient's room) and step end → an item_give trigger filtered to the recipient mob + the parcel item, with consume_item, an npc_say thank-you, and grant of the end token → rewards: gold + a player message. Grant yourself the start token with questtoken and run the delivery.

Behaviors

Read this first: the editor shows a TREE, not a list. Indentation is nesting — a row's children sit inside it under the dotted rail — and sibling order is EVALUATION order (a selector tries children top-down until one succeeds; a sequence runs them top-down and stops at the first failure). The ↑/↓ arrows are therefore game-mechanics controls, not cosmetics.

Three tree families share the tab:

FamilyScopeWhen to use
Archetypesshared — one file, worn by many mobs via the mob form's Behavior archetype dropdownspecies-wide AI: fighters, casters, foragers, shopkeeps. Editing one changes every wearer at once.
Per-mob treesone mob — a private COPY forked from an archetypebosses and named characters who need bespoke moves. The copy overrides the archetype entirely; delete it and the mob falls back.
Room treesone roomscripted spaces: command interception, entry/exit reactions, ambient machinery.

Forking vs assigning: "+ New mob tree" forks a private copy for one mob. To simply put a mob ON an archetype, use the mob form's dropdown — no copy involved.

Node anatomy

  • Type: selector / sequence (branch nodes with ordered children), condition (a check), action (a do), decorator (cooldown / repeat / invert / random / delay wrapping exactly one child).
  • Event gate: the node (and its subtree) only runs for that event. The 15-event vocabulary is enforced — an unknown event is refused at save, because at runtime it would be a silently dead node. (The caravan wagon's death-scatter was dead for months for exactly this reason.)
  • Params: checks and actions take free-form parameters as key/value rows — e.g. mob_health_below takes percent. The reference for each name is docs/schemas/behavior.md.
  • Note: per-node rationale that SURVIVES saves — use it where you would have written a # comment.
Try: feel the evaluation order: open generic_fighter, expand the mob_combat_round selector, and move its interrupt-bash sequence below the kick sequence — save, fight a thug, and watch its priorities change. Move it back. Then fork a per-mob tree for one boss and give only THAT boss a random 25% decorator around a taunt.

Where the tabs meet

No content stands alone. The builder's guards understand these seams — this is the map of them.

SeamHow it works
Rooms → Mobs/ItemsPlacement lives on rooms: a room's Spawns list names mob and item ids. A mob template never knows its spawn rooms — to move a mob, edit rooms. Deleting a mob or item is blocked by every spawn list that names it.
Mobs → DialogueA dialogue file belongs to one mob (its Dialogue… button). Deleting the file makes the NPC mute — the delete warns; nothing else breaks.
Dialogue ↔ QuestsThe load-bearing seam. Dialogue grants quest tokens (grantsQuest) and gates lines on quest state; quests declare the flags dialogue sets. The dialogue editor's token pickers list real quest steps; the quest editor warns when a step is granted by nothing; quest deletion is blocked by every dialogue gate that names it. Convention: dialogue owns quest OFFERS (talking to people), quest triggers own world events (giving, killing, arriving).
Quests → everythingTrigger filters and actions name mobs, items, rooms, buffs, spells, recipes, factions — all validated against the live registries at save.
Mobs ↔ BehaviorsThe mob form's Behavior archetype dropdown assigns a shared tree; the Behaviors tab edits the trees themselves and forks per-mob copies. Archetype deletion is blocked by every wearer AND by the mutation shift system (mutated mobs drift between archetypes — a missing target would strand them). Renaming a mob moves its per-mob tree automatically.
Zones → everythingZone rename rewrites the zone: field across rooms, mobs, spawns, behaviors, and dialogue paths in one guarded operation. Zone deletion is blocked by any surviving content or inbound exit.

A complete build, end to end

The full loop, touching every tab once — a hermit with a small quest:

  1. Rooms: pick or build the hermit's clearing; add a mossy shrine noun for atmosphere.
  2. Items: create the river pearl he wants.
  3. Mobs: create the hermit — non-combatant, described, modest stats; archetype noncombat_questgiver.
  4. Rooms again: spawn the hermit in his clearing; spawn river pearls somewhere findable (a container, a forage room).
  5. Quests: the fetch quest — steps with map targets, an item_give trigger (hermit + pearl) that consumes, thanks, and grants the end token; a small reward.
  6. Dialogue: his voice — greetings, a pattern about the shrine, and the quest-granting node (with both exclusions and quest/task triggers), plus an active-quest root variant.
  7. Behaviors: nothing! noncombat_questgiver already covers him — which is the archetype system working. If he needed a quirk (fleeing chatter when hurt), you'd fork a per-mob tree.
  8. Walk it as a player: find the hint, find the pearl, make the delivery. Every piece went live the moment you saved it.
In-game admin commands still exist (build, questtoken, cartcheck) and the builder rides the same engine seams — you can mix freely. questtoken in particular is the fastest way to put yourself at any quest step while testing.
